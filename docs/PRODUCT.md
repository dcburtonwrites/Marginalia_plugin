# Marginalia plugin

The current owner decisions in PROJECT-CONTEXT.md and DECISIONS.md govern. The reference mockup governs appearance; its generic book icon and “Suggest additions” are superseded.

- Desktop and mobile Obsidian for app navigation/pages and native comic script editing. Librarian uses local Ollama on desktop, with a selectable installed model. No cloud fallback or automatic model download.
- Left ribbon: winged M/nib opens Script Studio in the left sidebar. Right sidebar and native note-header action: lantern.
- Follow active note; pin holds current context. Ask / Review / Library tabs. Active-note context, references, local status, conversation and composer follow the mockup.
- Entry Enhancement and Entry Expansion appear beneath context only in the Review tab. Ask remains conversational and Library browses saved results. Enhancements provide finished section prose with source excerpts. Insert adds a single section addition using an undoable native editor transaction; Dismiss removes it. Pending suggestions and conversations are session-only, keyed to the target note. New chat clears that note's conversation; review suggestions remain available.
- Retrieval includes original target text, aliases, resolved links, incoming links, explicit mentions and bounded supporting lore. Script mentions retain adjacent same-page context. Declared blank fields are not facts. Ambiguous aliases must not merge identities. Exclude generated, research, archived and provisional sources from evidence-based entry writing. Sources, offsets and omission counts are inspectable.
- Expansions are supported synthesis, not invention. Store only under `.marginalia/expanded/<relative entry path>.md` through the adapter. Canonical source remains unchanged. Open in a plugin-owned read-only main tab/split with Generated / Not canon, original link, time, sources, staleness and Regenerate.
- Exclude expansions from canonical search/retrieval. No export or editable generated-note conversion in this increment.
- Preserve existing hidden artifacts. Read compatible standalone expansion metadata; never overwrite an artifact owned by the standalone app in this increment. Reject malformed files and competing changes.
- Errors and cancellation retain previous results. Source changes during generation invalidate the result. Changing context does not attach a result to a different note.
- Templater remains responsible for executing templates; the plugin does not run template code or alter native shortcuts or filing. Script ordering properties are maintained only by the script workflow below.

Deferred: remaining script editing/export features, mobile Librarian/network model connections, cloud, hidden-folder sync verification and legacy expansion migration. Placement immediately beside Source Control and note-header button ordering are host-controlled and require verification in Obsidian.


## Script organizer increment

- Left Scripts pane: project/group → script file → virtual page → virtual panel. Notes stay in native Obsidian editors; Longform is not required.
- Existing Preceded By properties determine reading order. Missing fields are automatically created from the unambiguous current sequence; the first script has an empty predecessor. Old plugin order only seeds migration/ties where links are absent. Do not overwrite conflicting, dangling or cyclic claims during automatic fill; show them for resolution.
- Dragging scripts within a project/group updates the complete predecessor chain in source frontmatter, including the old and new neighbors. Existing Followed By fields are updated as compatibility projections; they are not a competing authority once predecessor fields exist. New fields use full vault-relative wiki links without the .md suffix.
- Prepare and validate all property changes before writing. Reject stale snapshots and dirty editor buffers, atomically compare/write each file, and roll back prior changes when a later write fails if those files still match the plugin's write. Preserve newer author edits. This is not a cross-process multi-file transaction.
- Arrows alone expand/collapse each level; names navigate without toggling expansion. Script names open their notes, page names open the correct heading. Remove sidebar Move Up/Down, Open script/page and adoption buttons. Script ordering uses drag and drop.
- Project names open a continuous read-only reading view of all script notes in order, with groups shown separately and script headings linking back to native editors. No combined source file is created; closing/reloading restores the view from project state.
- No automatic filing or template execution.
- The Scripts outline updates through native vault, metadata, editor and workspace events; no manual Refresh control.
- A Double Spread ends on Right, so the next inferred or newly inserted page is Left, followed by Right. Explicit authored Side overrides remain valid.
- Display declared Pages separately from actual slots, show count mismatches, respect Side and two-slot Double Spread, and compute group ranges from actual parsed page slots (D-0037). Missing or stale declared counts are diagnostics and do not control numbering.
- Panel numbering resets per page and is display-only. Authored titles remain unchanged. Navigation opens the file at the selected page/panel in the native editor.
- Sidebar dragging reorders complete pages within a script and panels within or between that script’s pages. A panel dropped on a page header goes to the end of that page, including an empty page. Movement includes all owned source through the next sibling panel/page (dialogue, notes and overrides). There are no movement buttons. Commands insert a page/panel, move a page/panel up/down, and navigate to the previous/next page/panel. Structural edits use isolated native Undo; commands have no default shortcuts. Cross-file structural moves are excluded.
- Exact Enter slash commands are enabled in comic script editors (see below). Compilation and PDF export follow the agreed platform capabilities below.

## Script creation (D-0028)

Scripts settings includes a vault-relative Script template location with typing dropdown suggestions. The folder context menu in the native file navigator offers Create a New Script. Script Studio shows New Script below the last script in the active list, above the writing footer. Both use one dialog for a script name and grouping; the sidebar preselects the active grouping and uses the last listed script's folder. A project-wide selection stays project-wide. Blank grouping means Top-level. With no active selection, use the folder action to start a project.

Creation copies the current template source without executing template code, preserving its body and unrelated properties. The new note receives Title, role: manuscript, format: comic-script, Group and an end-of-group Preceded By link (empty for the first script); a copied Followed By field is cleared. Other source notes and the template remain unchanged. The new script opens in the native editor and appears in Script Studio. Copied text earns no writing credit. Missing template, malformed YAML, missing/excluded destination, invalid name, duplicate note and unresolved ordering warnings produce actionable errors without overwriting files. Template path follows native file/folder renames. Template, Archive and hidden folders are excluded destinations. Templater execution and compile/export remain separate.


## Script Studio and writing sessions (D-0012 / D-0013)

The M ribbon opens one native left-sidebar Script Studio tab. Its Project or grouping dropdown switches between all groupings in a project and a specific grouping; the scoped Scripts outline and writing footer remain in the same tab. Opening the tab preserves the main editor. A project opens its complete ordered reader and scopes Scripts to all its groups. A grouping opens that reader with only its scripts and scopes the sidebar accordingly. The project/grouping menu remains available above the outline; unrelated note navigation does not change the chosen writing scope.

Below the outline, above the vault bar, show a countdown and today's net new words. Settings independently hide each, change countdown duration, and set a daily goal. Modes are All projects (all recognized script notes), Current project (selected project, including its other groupings), and Full vault (ordinary Markdown notes, excluding templates/hidden storage). All modes measure today's tracked local editor changes, not current manuscript size. Opening notes/importing changes does not earn words; Undo/deletions adjust the total. Existing text becomes the baseline on startup, and local midnight resets daily totals. Counting excludes frontmatter and automatic script scaffolding. No historical/offline writing attribution is promised.

Start/Pause/Reset control the countdown. Default is 25 minutes; duration is configurable from 1 to 1440 minutes. Double-click the time (or focus it and press Enter/Space) to set a one-session duration. This leaves the settings default unchanged. Editing is blocked while running or paused mid-session; finish or Reset first. Reload restores remaining time paused and retains that session’s edit lock. Reset restores the settings duration. Sidebar pages start closed, showing panels only when their page arrow is opened. Goal 0 shows words without a target bar; Current project permits a separate target for each project. Hidden controls retain their tracking state.


View options in Script Studio offers two state-dependent controls for the most recent main script editor or project reader: Collapse all / Expand all, and Collapse panel descriptions / Expand panel descriptions. Expand all appears only while some content is collapsed; expanding panels alone leaves page folds intact. Collapse all folds page content; panel-only folding opens pages and hides only panel descriptions, keeping their titles, dialogue, notes and locations visible. Expand all reveals everything. These actions do not edit source. Ordinary notes are excluded. In native Reading mode, an individual script switches to editing before applying native folds. The project reader uses local disclosures. Compilation opens from the Compile PDF… button below the project/Group selector. Shortcuts are the next requested increment.


## Script typing shortcuts (D-0018)

Type an exact command on its own unindented line and press Enter in native Source or Live Preview. /P creates a page with the next local number and inferred Side; /p creates a panel without a Panel Description label; /d creates dialogue with SPEAKER selected and a local character picker when candidates exist; /t creates a quote callout for title/display. /c and /cn create a note, /ct a tip, /cw a warning, /cd a danger, /cs a success, and /ce an example. Callout placeholder text is selected for replacement. Commands are case-sensitive: /P and /p differ. /P can start an empty script; other commands require an existing page. In Markdown, the new block replaces the command line at the current cursor position; downstream authored text/headings are preserved rather than reserialized.

Conversion is one isolated native history step: Undo restores the typed command, and a further Undo can undo typing separately. Unknown commands, ordinary notes, templates (including _templates), code fences, indented/quoted/list text, frontmatter, HTML comments, math blocks, selected text and multiple carets retain native Enter behavior. Shift/Alt/Ctrl/Command+Enter and composition are not captured. Existing Obsidian/Templater key bindings and execution remain owned by those tools. No default OS shortcuts are assigned.

Empty shared folders qualify; nested folders become tabs within their own section. Creation, rename and deletion update the menu live. Keep the original M ribbon for Script Studio in its existing location. Home offers Continue Writing, pins and recents; Brainstorms/Canon use searchable cards and folder/category tabs; projects offer folder tabs and original-note links. Storyboard adds a status register. Shared areas have their own menu entries and searchable folder-tab pages, with no shared-area buttons inside Project Register. These views browse live vault notes and open the native editor. New Entry provides creation as described below; executing template commands and inline register editing remain outside this increment.

Settings has three collapsible sections, each with an immediate enable switch: Theme, Scripts and Librarian. Theme contains World/Storyboard selection, App colors and App navigation. App light/dark palette applies while colors are enabled. Module preferences survive disabling. Switching vault type does not migrate or rewrite notes. Disabling Theme removes its pages/menu/palette; disabling Scripts or Librarian removes only that feature's views/actions/listeners.

Templates in a top-level `_templates` folder are browsable only through that shared section; they remain excluded from Home/Canon cards, script recognition and Librarian evidence. Opening a template uses the native editor and does not execute it. The menu can scroll while preserving space for the native file tree.

## Dialogue character picker (D-0025)

After /d + Enter, show characters used in the current script: Characters/Character frontmatter (plain names, wiki links, aliases, arrays or comma-separated declarations), earlier dialogue speakers and known character-note names/aliases found in body text. Frontmatter-only characters qualify. Character notes are recognized by Character/Characters folders, character tags or character-card role. Do not list unrelated links or every character in the vault, and do not guess uncatalogued proper nouns. Skip code/comments/images; scene/Side/SFX labels are not speakers.

On desktop, use the inline dropdown: type to filter; arrows choose; Enter/Tab or click accepts. Keep the used plain/wiki form, preferring existing dialogue usage. Remove delivery qualifiers like (OFF) from the candidate name; do not rewrite earlier dialogue. Identifiable ambiguous aliases remain separate choices with note paths. Accepting selects Dialogue for typing. Escape closes without changing speaker text, and unknown/new names remain freely editable. Empty casts keep the existing editable SPEAKER behavior. On desktop, selection outside the speaker, edits outside its range, blur, or Undo dismiss the picker. Choice is a separate undoable edit; conversion retains its isolated Undo. Only script editors and the Scripts module own these keys.

Templates are matched by configured path or matching template filename when available. Users may override the path or leave it blank for an empty note (scripts require a template). Folder/template/project inputs suggest local vault items as the user types.

New Project creates a named folder with Overview.md. Project children stay within the selected project. Creation preserves template bodies and unrelated metadata, fills Title and type tags, and reuses script creation for scripts. Duplicate files/projects, invalid destinations/templates and disabled script support produce inline errors. The setup offers instructions, Save, Cancel, Restore defaults and Create missing folders. Saved routing controls new entries and live canon/project discovery, without migrating source. Type names must be distinct and cannot collide with the fixed entry/project options.

Home’s Pinned References header shows Edit by default. Edit reveals a labeled searchable selector and unpin controls; Done hides them while pinned cards remain visible. The selector accepts typed note names/paths and matches the native Find an entry search input in style, height and responsive 260px width. The same editing behavior applies to Storyboard Pinned Projects. Librarian reference selection uses the same typing interaction with an entry-type filter. Both only reference existing eligible notes. Template paths, destination folders, project selectors, grouping fields and metadata settings use local suggestions; free-text values remain possible where relevant. No remote lookup or model generation is involved.

Main module settings share a two-column layout: explanatory text wraps on the left, fields/selectors use a consistent width on the right. Buttons and toggles retain their native size and right alignment (D-0032).

## Mobile scope (D-0033)

The manifest permits mobile loading. World/Storyboard app navigation remains above the native file viewer; Home is also available as a command independently of the explorer. App pages use the native main pane and close the left drawer after navigation. Script Studio uses the native left drawer; selecting a scope or script reveals the main reader/editor and closes the drawer. Pages start closed as on desktop. Touch controls have larger hit areas and phone fields can stack beneath their descriptions.

Script slash commands keep native CodeMirror editing and Undo. Hardware Enter uses the existing keymap. iOS soft-keyboard paragraph/line-break events use the same guarded planner; Android retains CodeMirror’s deferred native Enter handling so IME/DOM updates can settle first. Composition and unrelated input remain native. On mobile, /d opens a native Choose a character dialog when candidates exist. Search and tap a character, or type a new name and tap Use this name. Repeated Enter/Tab or soft line breaks never accept the first result. Cancel keeps SPEAKER selected for direct typing. A choice selects Dialogue and remains a separate Undo step. Mobile does not rely on the editor tooltip and does not dismiss picker state when focus enters the dialog. A changed source/file blocks stale insertion, and editor destruction/module unload closes the dialog. Vault suggestion options retain touch support.

Librarian does not start, connect, register AI commands or add note actions on mobile. Its settings section explains desktop-only availability instead of exposing model/connection controls. A restored desktop Librarian or expansion tab shows the same explanation. This runtime restriction never overwrites the saved desktop module/model preferences. Connecting to a computer on the LAN is technically possible with Ollama but is outside this version’s loopback-only transport boundary. No inference runtime, cloud service or networking permission is added.

Mobile verification currently covers bundle loading without Node APIs and browser phone/tablet interaction profiles. Physical iOS/Android sidebar placement, keyboard/IME behavior, storage and sync acceptance are still required before declaring mobile release readiness.

Hidden folders controls only Marginalia menu sections; it does not hide notes in the native file viewer or change the general entry/model evidence rules. When a currently open shared section becomes hidden, its page returns to Home. Unhiding _Assets permits browsing its Markdown notes within its shared section.


## Optional writing tools (D-0036)

Groups provide draft separation. No independent draft-version feature is introduced.

Settings → Scripts offers Focused writing, off by default, and a user-bindable toggle command. Recognized native script editors dim surrounding paragraphs and keep the typed line at the visible editor midpoint on desktop, or one-third down the visible editor on mobile (D-0038). The target follows keyboard/viewport resizing; spacing at both document ends permits the same position near the first/last lines. Navigation stays accessible. Normal notes, document text, selection and Undo history remain native; disabling Scripts removes the editor presentation.

Record session history is independently off by default. When enabled, new countdown sessions record start/finish, initial project/group selection, active timer minutes, local added/deleted/net words and outcome. Paused/offline time and imported changes are excluded. Completion or Reset finalizes a record; pauses/reload preserve a resumable record. Turning tracking off finalizes the current record without deleting previous history or stopping the countdown. Existing daily counts remain independent. Data stays in plugin settings, with up to 500 finished records and no note contents. It is not a merged cross-device history.

History & progress in the footer, Scripts settings, and a command opens a report with session rows, rolling 7/30-day totals, CSV export to a new vault file, and confirmed clearing. Initial scope is a label, not a filter: session word totals cover all eligible notes edited while the timer runs. CSV protects spreadsheet-formula prefixes. Clear removes recorded history, including the active record, while preserving the countdown and daily totals.

Compilation opens from Script Studio’s Compile PDF… button or the Compile scripts to PDF command. Choose one Group; the pop-up offers an included-scripts checklist and a Content Selections section containing Panel Descriptions, Callouts and Notes and Title page. All three default on for fresh options; saved explicit choices remain respected. Presets are removed (D-0040). Title page reveals a required author-name field, prefilled from the most recently previewed title-page author in this vault and editable for each print. The name is shared across Groups within this vault. Title pages show the Group followed by the current local date and a By author byline; date and author are snapshotted when building the preview. Advanced options select Letter/A4, numbering restarted per script or continued through the original Group, new PDF sheets per script, metadata and PDF sheet numbers. Inclusion/preferences persist per project and Group. Ordering issues block compilation until repaired; Groups are never mixed. Continuous numbering retains excluded scripts’ original Group positions.

Desktop Preview PDF opens a main-pane preview of the generated PDF, with sheet navigation and Export PDF… through a native save dialog. The exported bytes are those shown in the preview. Source or included-image changes invalidate export until rebuilt. Cancel closes the dialog without writing; export writes through a temporary sibling before replacing the selected destination. Obsidian desktop hosts without the local print capability show an explicit explanation and readable script preview.

Mobile has the same compilation options and a script preview, with PDF export disabled and a desktop explanation (D-0039). It does not promise physical PDF pagination. Source notes, editor folds and writing history are unchanged. Frontmatter is omitted unless metadata is requested; author comments are omitted. Supported local raster images are embedded (20 MB each, 100 MB total); external images, unsupported assets and embedded notes receive visible omission warnings. PDF output uses its own styles and expands panel bodies according to the chosen option. EPUB is out of scope. See PDF-COMPILE-NOTES.md.

Reading view, Script Studio and the continuous project reader calculate page labels from the current source sequence, ignoring literal numbers in headings. Named headings retain their names; Double Spread consumes two slots. Named and unnamed panels display Panel 1, Panel 2, etc., restarting on each page. Existing numeric panel labels are replaced in the display, not duplicated. Group ranges use actual slots; declared Pages remains author metadata with discrepancy warnings.

Numbers update after insertion/deletion, including later rendered sections Obsidian reuses. Authoring source/Live Preview retains literal headings/callout titles; save/switch to Reading view for authoritative rendered numbers. A `## Page ?` placeholder is supported. No automatic renumbering writes, editor transactions or Undo entries are introduced. Inline title links/emphasis remain intact in rendered notes. Compiled PDF and mobile script preview use these same numbering rules. Author comments and fenced examples do not contribute structural page slots.

## Librarian reliability — D-0041

Project-local evidence follows the configured project root and vault type, including root-level Storyboards and custom nested roots. Configured global canon folders and shared underscore areas stay shared. Filter unrelated projects before duplicate-identity detection, incoming/outgoing references or supporting-source expansion; explicitly pinned references cannot override this boundary. The source disclosure includes exclusions.

Ask answers the question without inheriting entry-writing sections. Citations resolve only to supplied original notes: exact paths, unambiguous titles or source IDs. Repair a comma/source-ID suffix only when its named note and source ID agree. Unknown/ambiguous references become nonclickable text with a notice. Apparent unfinished endings, absent original-note citations and context-budget omissions receive per-answer notices. Model-reported output-length truncation continues to fail without publishing a partial answer. Native citation navigation opens an existing original file; a missing file never creates a new note.

Writing briefs preserve who did, said, suspected or dreamed each event. A scene location does not establish ownership; a proposed repair is not a completed repair. Direct target evidence governs length, with no expansion minimum or inferred personality/backstory to fill headings. Obvious unfinished prose is rejected before suggestions or saved expansion replacement. A deterministic non-observation check blocks supported patterns where "no event is shown" becomes "no event occurs" without an explicit denial in the evidence. Enhancement, Expansion and refinement then receive a separate local-model evidence review. A flagged draft gets at most one correction using original evidence and is reviewed again. A second flag, or an unreadable/invalid verdict, withholds the new result and retains previous results; sources are verified again after review. This normally adds one local review generation, with up to one correction and another review when needed. The reviewer is conservative and can make mistakes; these safeguards are not a proof of accuracy, and author judgment remains required.

Configured canon types and literal headings from their selected template guide writing. Built-in types retain their specific brief; custom types receive a named neutral brief. Project overviews receive project-brief sections and preserve planned versus completed story events. Conditional Templater source is never executed or interpreted; use the type defaults/existing headings instead. Templates are excluded from evidence/citations but fingerprinted for section freshness. Storyboard Librarian labels say This project.

## Saved Librarian outputs and insertion spacing (D-0042)

- Section insertion removes the chosen section's trailing placeholder blank space before adding prose. Existing prose, frontmatter and neighboring sections stay intact; one native Undo restores the whole edit. CRLF notes retain their newline convention.
- Library lists unsupported/damaged outputs with a preservation notice instead of silently omitting them. Older standalone generated Markdown can be inspected read-only even when its structured expansion cannot be decoded. Such prose has no verified source/freshness status. Compatible standalone outputs cannot be regenerated over by the plugin; ownership migration remains deferred.
- Replacing a plugin-owned output retains one previous version at `.marginalia/recovery/<relative entry path>.md`. “Restore previous saved version” is explicit, is unavailable during another operation, verifies ownership and competing changes, and retains the replaced version as the next recovery copy. Damaged plugin-owned primary files or missing primary files can be recovered when a supported plugin copy survives. This is one previous version, not an archival history or a cross-process transaction.
- New results detect original-source changes and changes to the possible-evidence inventory: shared eligible originals and originals in the target project, including newly added notes. Global/world entries consider all eligible projects. This deliberately conservative check can flag an unrelated edit in that scope. Configured classifications, template routes and context budget also invalidate prior results. Older saved expansions disclose that only their original source list can be checked.
- Portable output and recovery files use vault-relative paths and embed their original text/excerpts. Local copying between two synthetic vault roots is tested. Delivering the hidden `.marginalia` folder through the owner's sync setup and reopening on a second desktop still requires physical acceptance; a plugin setting alone cannot establish delivery.


## Project recognition and responsive navigation (D-0043)

Project lists, New Entry destinations, Script Studio, current-project writing credit and Librarian use shared project boundaries. Configured roots and canon/brainstorm routes remain authoritative; project-parent tags (frontmatter or indexed inline), project-role overviews and safe Project properties support explicit custom layouts. Existing manuscript/Scripts layouts remain recognized. Numbered or unnumbered Overview, Dashboard, Index and Project Register folders are organizational containers; they do not become projects merely by position or an overview tag. An explicitly marked real project nested within a container can still be recognized. Shared, hidden, template and archived areas stay outside project membership. Nothing is moved or renamed to establish classification.

Desktop sidebar movement uses a mouse drag; touch uses a deliberate long-press before moving. Ordinary touch scrolling cancels an unstarted drag, cancellation changes no source, and visible drop lines identify the target. Page/panel drops onto another script are ignored. A stale outline or changed editor blocks the operation instead of applying old offsets. Dialogue, comments, quoted descriptions and side overrides move with their owning block; authored headings stay intact while displayed numbering is recalculated. Navigation commands move the cursor without changing text and can leave a selected passage. Structural movement requires a clear selection when invoked by command.

Unchanged script text reuses parsed structure and guarded native read caches. Editor buffers take precedence over saved text. Ordinary prose edits update live navigation/drop offsets without rebuilding the outline; structural changes redraw it while preserving disclosure and scroll state. Project readers reuse unchanged script articles, including their fold state. Coalesced refreshes prevent overlapping scans from accumulating. These optimizations do not skip final text checks before structural moves or ordering writes.
