# Initial architecture

Native TypeScript Obsidian plugin, compiled with esbuild; no runtime UI framework. Official Obsidian API supplies views, settings, metadata, Markdown rendering, note navigation and native editor transactions.

- `src/core`: host-independent retrieval, prompts, output validation, insertion planning and expansion envelope validation. No canonical file writer is available to model generation.
- `src/ollama.ts`: loopback-only model selection, capability checks and request budgeting. No cloud models or fallback. Installed model selection is explicit.
- `src/transport.ts`: desktop Node HTTP, loaded lazily only when a request begins, without redirects. Assemble Ollama NDJSON streams and publish only after their final completion marker. Surface waiting/thinking/output progress without displaying or persisting partial drafts. Separate connection, HTTP/API, invalid-response, cancellation and timeout failures. Generation allows 180 seconds of idle time and a 10-minute overall deadline; metadata uses 15-second idle and 30-second overall limits. These limits are not proof of why a particular model run stalled.
- `src/ui`: shared DOM component and namespaced styles using Obsidian theme variables. System typography, native background/border/text colors and purple host accent match the supplied mockup. Left alignment; small contextual cards, prominent entry actions and composer anchored at bottom. No extra dashboard or decorative branding.
- `src/main.ts`: Obsidian lifecycle, read-only vault snapshot, hidden adapter storage, session state and guarded native editor insertion. Save plugin settings through Obsidian. Expansion data stays out of `getMarkdownFiles()` and is never indexed as evidence.
- `src/prompts`: adapted source-grounding brief and type guidance from the standalone app. App-specific indexing/runtime modules are not imported.

Storage follows the inspected standalone `expansion` frontmatter envelope, adding a plugin-owner marker. Legacy artifacts can be read where their draft/schema is supported; replacement requires a future explicit migration. A pre-write comparison detects competing changes, but is not a cross-process transaction; simultaneous standalone/plugin writes to the same vault are unsupported. Development uses synthetic fixtures and does not access the creative vault.

Tests exercise rules and host boundaries with synthetic data. A browser harness mounts the same sidebar component for visual and interaction checks; it is not evidence of installation or actual Obsidian rendering.


## Script organization

`src/scripts/model.ts` provides source-range parsing, predecessor order diagnostics, page slots and edit planning. `src/scripts/properties.ts` patches ordering fields while preserving the body and unrelated block-mapping YAML; valid unusual flow/complex YAML uses the host serializer fallback, which may normalize YAML formatting/comments. `src/scripts/controller.ts` reads current script metadata through Obsidian's YAML codec, validates transformations, fills missing predecessors and coordinates guarded order writes. `src/scripts/view.ts` registers the left ItemView, separate disclosure/navigation controls, drag ordering and native structural commands.

Preceded By is the order authority. Existing `scriptOrders` in Obsidian plugin data supplies only a migration/tie seed for notes without established predecessor links; new drag order is represented by canonical predecessor properties. Legacy Followed By is used only to seed a group with no predecessor fields and is maintained on drag where already present. Longform is optional and is not another order authority.

Ordering writes use Obsidian `vault.process` for atomic per-file comparison/write, whole-group preflight and a final comparison, with conditional rollback of already-written files on failure. The coordinator rejects unsaved editor buffers and preserves subsequent author edits during rollback. Multi-file writes are not crash-atomic or a cross-process lock; a crash/interruption or competing external editor can leave order issues to diagnose and repair. Missing-field maintenance runs on layout/metadata/vault changes as well as view open. No model-generation writer gains access to this path.

`src/scripts/project.ts` renders a read-only continuous project ItemView from the same ordered groups, using native MarkdownRenderer with each source path for links. It stores only project/group view state, creates no merged file, and refreshes on script changes. Notes remain separately editable in MarkdownView. Page/panel structural edits still use one native editor transaction.

Tests exercise field precedence, missing fill, drag property plans, source preservation, stale input, partial write rollback, dirty buffers, separate arrow/name actions and project content order. The browser harness uses the same view/controller implementation with fictional files and a limited flat-YAML test codec; real Obsidian validation remains necessary for the native YAML codec and host interactions.


The script outline and project reader update from native metadata/vault/editor/workspace events with a short debounce; there is no manual Refresh control. `followingSide` is shared by outline parsing and page insertion: a spread ends on Right and is followed by Left. Explicit authored Side metadata still overrides inference. The display correction does not rewrite existing notes.


## Writing sessions

`src/scripts/view.ts` registers the unified Script Studio ItemView under marginalia-scripts. `openStudio` creates/reuses a leaf under `workspace.leftSplit`, leaving the main editor intact. The legacy marginalia-script-studio registration is retained only for workspace restoration; layout-ready migration replaces/retires its leaves after the unified tab is ready. The project/grouping menu is always above the scoped outline. The shared script controller persists `{scope, group?}` selection and filters the outline through `selectedGroups`; it captures the current main leaf before revealing the sidebar so scope changes reuse the intended tab. The existing project reader renders the chosen scope, without copying source files.

`src/scripts/writing.ts` owns validated preferences, local-day totals, per-project goals, runtime word baselines and countdown deadlines. Editor-change events earn signed word deltas; startup reads and vault modifications only update baselines. Baselines contain counts and project identity, never note text, and are not persisted. Word extraction excludes frontmatter, script structural labels, fenced code, comments and image targets. Hidden/template paths and non-Markdown attachments are excluded. Rename transfers baseline identity and project state without credit. `Intl.Segmenter` supplies visible-word segmentation.

`session-ui.ts` renders the footer outside the outline's scrolling region, preserving focused timer controls on periodic redraw. A one-second lifecycle interval ticks the clock and announces completion once. Remaining time is snapshotted into plugin data; reopening restores paused. Editor totals save after a short debounce, with a periodic flush during continuous typing; unload pauses and flushes. Settings, script-order migration data and writing state use the same save queue. `settings.ts` uses native Obsidian controls; independent visibility toggles are presentation preferences. This is local plugin state, not historical attribution, a synchronization guarantee or a cross-device timer.


`src/scripts/folding.ts` captures native EditorView references via Obsidian's editorInfoField and a registered CodeMirror ViewPlugin. Native foldAll/unfoldAll handles headings; CodeMirror foldEffect handles panel quoted-body ranges, excluding following dialogue/notes. A scoped Live Preview class hides atomic panel-widget bodies that otherwise render above native folds; it clears when the file changes or Expand all runs. Native folds do not change cursor selections, and the controller does not reapply selections afterward: CodeMirror would reopen the page containing the cursor. Parsed page ranges explicitly fold every page, including Double Spread. No transaction changes document text. CodeMirror/Lezer packages are host externals in the plugin build; @codemirror/language is a development dependency. `ProjectView` wraps rendered page/panel blocks in local HTML disclosures and applies the selected fold mode after redraw. Its original source files remain untouched. Compilation has its own rendering pipeline below; folding remains independent.


Fold-control labels query actual native folded ranges/Live Preview state or rendered project disclosures. The sidebar refreshes these labels after actions and on its lifecycle tick so manual folds and navigation are reflected. The panel expansion action removes only panel folds and the Live Preview panel class, preserving page folds. ProjectView tracks page and panel state separately for redraws.


## Script typing shortcuts

`src/scripts/shortcuts.ts` plans an exact command-line replacement against current source and script metadata, with protected-context checks and explicit typing-selection offsets. It uses the shared parser/side rule and preserves surrounding source/line endings. The script identity guard now also excludes _templates directories. `shortcut-extension.ts` registers a highest-priority CodeMirror Enter keymap via the existing plugin editor extension registration; nonmatching input returns false to the host. `editorInfoField` supplies the current file/editor, and the planner reads current buffer YAML rather than stale cached identity. Single empty selection and composition guards run before planning. No main-window DOM key interception or native hotkey reassignment is used.

A single CodeMirror document/selection transaction commits the replacement, annotated with `isolateHistory(full)` and input.complete. @codemirror/commands is a development dependency for the host's native history API; CodeMirror/Lezer remain external in the production bundle. Tests verify the actual CodeMirror history boundary, not a matching imitation. Templater is never invoked or replaced. Existing sidebar/fold/AI boundaries are unchanged.


## App workspace and feature lifecycles (Phase 7)

`src/workspace/model.ts` validates per-vault module/layout/color/navigation/pin/recent state and classifies live note metadata. `src/workspace/feature.ts` registers the marginalia-pages ItemView. It reads metadata and current editor buffers/cached source, renders text-safe previews, and opens original notes with native link navigation. Only local plugin preferences change for pins/recents/layout; pages do not copy or rewrite notes. Empty project folders remain discoverable. World uses numbered canon/projects folders; Storyboard uses top-level projects and shared underscore areas.

WorkspaceFeature mounts navigation above file-explorer controls through its public view container and observed `.nav-header` / `.view-content` structure. This DOM integration was verified in Obsidian 1.14.4; it is not a dedicated stable file-explorer extension API. MutationObserver and native events maintain mounts, with unload/animation-frame guards and complete cleanup. Native controls/tree are retained. The Home command works independently of an open explorer. Palette variables are scoped to a removable body class; page headings use Source Serif 4 when available with Georgia fallback.

Main owns persisted settings and creates/unloads child Plugin instances for Theme, Scripts and Librarian. Registrations, commands, events and editor extensions belong to each child lifecycle. Disabling detaches only feature-owned leaves, preserves source editors/preferences, pauses writing state and aborts Librarian work as appropriate. Settings save must succeed before runtime changes apply. Existing AI/writing/order/workspace state shares the save queue. The M ribbon belongs to Scripts; it is not duplicated in app navigation. Three collapsible settings sections expose immediate module switches and disabled individual controls when off.


Shared navigation is discovered from loaded top-level TFolder paths through sharedFolders, navigation and sectionName in workspace/model.ts. Shared routes persist the exact folder path (for example _Research), keeping folder labels distinct from core routes; collisions with core labels display “(shared).” Legacy named shared routes map to existing folders. Folder events rebuild only plugin-owned navigation and redraw views; an application rename transfers an open shared route to the new path. Removing a section falls back to Home. External filesystem moves may arrive as delete/create and likewise fall back safely.

Shared pages filter the exact root folder and use their direct subfolders as tabs. The scoped sharedEntry inclusion permits templates within their own section without adding them to global entry eligibility, Canon, scripts or model retrieval. Nonthrowing bodyOffset allows incomplete Markdown/template frontmatter to remain browsable. Files stay in native editors; Templater execution is untouched. Dot-prefixed paths stay excluded; Assets shared browsing is allowed when its root is absent from the configured hidden menu folders. General entry/retrieval eligibility remains unchanged. Progress/runtime/model code is unchanged by this navigation increment.


Project Status Flow is persisted in WorkspaceSettings.projectStatusField and projectStatusOrder through the existing save queue. readWorkspace supplies legacy defaults; readStatusOrder normalizes newline/arrow input and removes duplicate, blank and reserved navigation labels. projectStatuses and projectStatusTabs provide the shared Storyboard lookup/tab policy to both register and card views. Native Theme settings save and refresh views immediately without rebuilding the settings form. Status configuration never writes frontmatter and does not change model retrieval, script ordering, shared-folder navigation or World card lookup.


## Local dialogue suggestions

scripts/speakers.ts extracts/deduplicates ranked speaker candidates from the current script buffer, its frontmatter and a metadata-only registry of character notes. Wiki identity uses native link resolution relative to the script; tags/aliases are read from metadata cache. It reads no other note bodies and invokes no model. Existing dialogue > declarations > wiki mentions > plain known-name mentions determines preserved insertion form; ambiguous alias identities are not silently merged.

speaker-picker.ts uses public CodeMirror StateField/StateEffect/showTooltip and scoped keymaps, registered through the existing child Scripts plugin. Shortcut conversion opens the picker in the same transaction that selects SPEAKER. The state maps an editable name range through typing, filters cached candidates locally, closes on outside edits/selection or blur, and offers keyboard and accessible button/option activation. Choosing a name replaces only that range, selects the Dialogue placeholder and creates its own isolated native history event. Tooltip nodes use textContent and document ownership from the editor. Module unload removes the field, keys and tooltip with its editor extensions. No global keyboard listeners, private host hooks, library installs or remote requests are introduced.

## Template-based script creation

WritingPreferences.scriptTemplate stores a vault-relative Markdown path, defaulting to empty for existing installations. Scripts settings offers a native path input with local typing dropdown suggestions. The Scripts child plugin owns a public workspace file-menu event for TFolder targets and the outline's New Script button; disabling Scripts removes both through the existing lifecycle. Native file-menu source labels are not assumed. Rename events update the configured path for a template or ancestor folder.

## Authoring controls and vault setup

WritingData.timerStarted distinguishes a fresh timer from a running/paused session, including reload restoration. WritingSession.setDuration only changes timerRemainingMs before starting or after completion/Reset; preferences are untouched. TimerDurationModal is opened by clock double-click or keyboard activation. The footer caches a render signature and updates only clock text during ordinary ticks, preserving the clock DOM between clicks. Sidebar page disclosures use their own expandedPages set, empty at view open, independently of main-editor folds.

ui/suggest.ts is a shared free-text combobox/listbox with local substring filtering, Arrow/Enter/Tab/Escape, mouse selection and document-owned dropdowns. Items come from loaded vault files/folders or metadata-cache property names/values. It does not access the network or execute template code. Home pins persist in existing workspace settings; Librarian reference chips remain in the existing per-note session. Reference type labels use configured canon mappings, frontmatter/inline tags and script identity.

workspace/setup-model.ts validates per-vault CanonType rows and EntrySetup routes. Defaults mirror the owner's numbered canon folders and _templates hierarchy; fixed project subtype routes remain ordered. Custom labels produce valid hyphenated type tags. WorkspaceSettings persists both maps in the existing save queue. AppPage classification prioritizes configured folders over tags; configured roots, explicit project-parent overviews and legacy paths supply project discovery. Canon filters consume configured types rather than requiring numbered folders; Brainstorms also recognizes brainstorm tags outside its mapped folder. Existing source is never migrated.

workspace/setup.ts owns a native editable table modal with local drafts, save rollback, cancel/defaults, explicit configured-folder creation and typed folder/template fields. NewEntryModal in workspace/creation.ts renders Entry type first, an optional subtype/project selector, then title/destination/template and folder-creation choice. Configured templates are matched exactly or by a matching filename within template folders. The service validates names/paths/templates and project containment before mutation, patches only title/type metadata while retaining the template body, and uses vault.create for non-overwriting writes. A per-owner mutation guard serializes entry creation; failures remove only still-empty folders made by that operation. Scripts delegate to ScriptController.createScript with a per-operation template override, preserving the saved script-template setting. A plain vault-relative Project property retains project scope for nonstandard script folders, accepted only when the note lies beneath that path. Module checks remain in creation paths. No Templater execution, private host hooks, additional runtime dependencies or generation optimization is introduced.

scripts/creation.ts provides a shared native Modal for filename/grouping entry and inline errors. ScriptController.creationFolder uses the active ordered list's last parent folder (with existing scope/Scripts or scope fallback). createScript validates the destination/name/template, reads the live template buffer when available, parses YAML, and uses propertySource to patch only identity, grouping, title and order fields. The body remains byte-for-byte unchanged; executable template syntax is never evaluated. A new script links to the current grouping's last script, without writing previous notes. Unresolved ordering warnings block appending. The controller busy guard serializes creation with ordering maintenance, and vault.create provides non-overwrite collision behavior even after preflight. Successful creation primes a zero-credit word baseline, updates selection while retaining project-wide scope when appropriate, opens the native editor, and reveals Script Studio. Failures after file creation in preference persistence/navigation are logged without turning successful creation into a retry. The existing multi-file ordering crash/concurrency limitations still apply; this is not a cross-process lock.

## Mobile platform boundary (D-0033)

Platform.isMobile gates the Librarian child lifecycle, connection/generation entry points, settings controls and note-header actions. Main registers lightweight message-only view factories for restored desktop Librarian/expansion leaves on mobile. Desktop settings remain persisted unchanged. src/transport.ts has a type-only Node HTTP import; the actual require occurs inside the desktop request path. Importing the production bundle or constructing its default transport never requires Node. Desktop streaming, timeout and endpoint rules remain unchanged.

Workspace page navigation and ScriptController/ScriptsView navigation collapse workspace.leftSplit on mobile after the destination is open. Public Obsidian leaves, vault adapters and native CodeMirror remain the only editing/storage architecture. Mobile iOS beforeinput routes cancelable paragraph/line-break events through the same shortcut transaction and character chooser; Android keeps CodeMirror’s own delayed Enter/IME pipeline. Touch pointerdown preserves focus for suggestion choices. Production CSS uses body.is-mobile for touch targets, phone settings and page sizing; desktop settings columns remain unchanged.

scripts/verify-mobile-load.mjs evaluates the actual production bundle with Node modules unavailable, then verifies the selected child lifecycles and restored mobile messages with a synthetic host. It does not execute those child lifecycles as a real device would. scripts/test-mobile-ui.mjs mounts production page/nav/Script Studio components and a real CodeMirror editor inside a simulated drawer shell; Chromium device profiles do not establish native WebKit/Capacitor or physical-keyboard compatibility.

WorkspaceSettings.hiddenFolders defaults to [_Assets] only for missing settings; readHiddenFolders normalizes an explicit string/array list without reintroducing defaults when empty. sharedFolders/navigation/sharedEntry accept that same list. WorkspaceFeature passes it through menu mounting, section migration/validation and scoped shared-entry browsing. The main Theme settings textarea saves through the existing queue and refreshes live. The two page search/reference inputs use type=search and marginalia-page-search, with a matching width constraint on the reference suggestion wrapper (D-0034).

## Mobile dialogue selection (D-0035)

scripts/mobile-speaker-picker.ts uses the public Obsidian Modal with an unselected list of explicit buttons, a local search/name input, Use this name and Cancel. speakerPicker retains the same source ranges and candidates but its tooltip provider is disabled on Platform.isMobile. acceptSpeakerKey consumes pending mobile picker acceptance keys without choosing; chooseSpeaker rejects an implicit candidate on mobile. iOS beforeinput uses that same guard, and Android’s native deferred keymap handling remains intact. Desktop key behavior is unchanged.

The mobile dialog opens in a microtask after shortcut commit, preserving the state across editor blur. It snapshots the CodeMirror document object and original file path, checks both plus attached DOM before applying a choice, and delegates to chooseSpeaker for the existing history/selection transaction. Cancel clears picker state without source edits and restores editor focus. A WeakMap and mobile-only ViewPlugin destruction hook close owned dialogs without dispatching into destroyed editors. No model calls, new persistence or dependencies.


## Optional focus and history (D-0036)

`src/scripts/focus.ts` registers a CodeMirror ViewPlugin scoped to recognized scripts and the Scripts module lifecycle. Decorations/style classes emphasize the current paragraph; measured scroll positions place the cursor without editing the document. The owner window visualViewport and scroll-container bounds determine visible height; desktop uses 1/2, mobile 1/3. Scoped computed padding permits first/last-line positioning. ResizeObserver, viewport resize/scroll and composition-end hooks refresh geometry; destruction removes listeners, padding variables and classes. Measurements and style writes occur in separate CodeMirror phases. Setting/command changes refresh open editor views. No body-wide focus classes, new dependency or replacement editor.

WritingData adds opt-in preferences, validated bounded session records and one resumable active record in the existing plugin save queue. WritingSession accounts only running countdown intervals, capped at deadline; signed local editor deltas supply additions/deletions, including Undo. Runtime time-accounting anchors are not persisted, so reload resumes paused without offline credit. History reporting is a native Modal; explicit CSV export is the only new vault writer and creates a new file. No document contents are recorded. Daily counting remains independent of history. The preview host exercises the production extension and report components against synthetic scripts.


## Structural display numbering (D-0037)

Shared pageLabel/panelLabel helpers in model.ts use parsed page.local/slots and panel position, preserving named titles. Organize/arrangedGroups accumulate actual slots rather than declared metadata. numbering.ts applies source-line-matched labels through the public Markdown postprocessor/context API, plus the continuous reader's full-script render. It changes text nodes only, preserving inline links, native fold controls and event handlers. Original text is restored by MarkdownRenderChild unload and module cleanup.

Rendered sections are tracked per source path. Native modify/metadata/editor events debounce a refresh across every live section for that file: Obsidian can reuse unchanged chunks after a middle insertion/deletion. A per-path revision guard rejects stale reads; identical source snapshots reuse parsing. Non-script sources are excluded, timers/cache/render children are lifecycle-owned. No canonical writer or source renumbering is added. Live Preview/source literal numbers are not authoritative; Reading view and the outline are.


Librarian initialization uses Workspace.ensureSideLeaf after layout restoration with active:false/reveal:false. Existing view types and deferred saved view states are checked before creation; an in-flight promise coalesces calls. The startup timer belongs to the feature lifecycle, and creation finishing after disable/unload is detached. The explicit settings action reuses the existing openLibrarian path.


## Compilation boundary (D-0039)

`compile-model.ts` validates saved options, isolates a single ordered Group, snapshots source/fingerprint and numbering offsets, and transforms comments, descriptions and headings without writing notes. `compile.ts` owns the native Modal and preview ItemView, renderer Component, resource resolution, stale checks and cancellable view lifecycle. Compilation preferences and one shared compilationAuthor live in the existing WritingData persistence; the obsolete preset key is ignored when loading preferences. CompileJob snapshots the author and creation time for consistent cover rendering; previews/source content/PDF bytes are held only in memory. Restored previews require an explicit rebuild.

`compile-pdf.ts` lazily loads desktop-only Electron remote capabilities for a hidden sandboxed, isolated BrowserWindow (Node disabled). It receives sanitized static HTML, an explicit title, self-contained print CSS and data-encoded local raster images. A restrictive CSP prevents network/script loads; navigation/new windows are blocked. Fonts/images settle before native printToPDF. The window is destroyed on completion, error, view close/module unload or timeout. Electron/remote/Node remain build externals and are never required on mobile startup. The private host capability is checked at runtime; failure is explained instead of offering a nonfunctional export.

The official loadPdfJs API renders the generated bytes one sheet at a time. Export uses those same bytes and a native destination/overwrite dialog. Source order/text and asset timestamps are revalidated before save and after the dialog; temporary-file plus rename protects earlier output from a failed write. The bridge has no network service or PDF-library dependency. Mobile renders the semantic compilation only and cannot invoke the desktop bridge.


## Librarian context and answer validation (D-0041)

`core/context.ts` adapts configured workspace project/entry classification to retrieval and selects a neutral project brief. `retrieve` accepts a pure scope resolver; the host passes configured roots, and the legacy default remains available to direct core callers. Scope filtering precedes identity disambiguation and graph expansion. Shared canon paths are not promoted to root Storyboard projects.

`core/answers.ts` canonicalizes links against the request’s target and actual source passages (not template freshness stamps), resolves source IDs conservatively and returns per-answer disclosures. It also detects obvious incomplete prose endings; this heuristic is not a semantic validator. Existing transport completion/length checks stay authoritative for interrupted streams. `core/writing.ts` uses the same link normalization, removes word-count pressure and rejects apparent unfinished sections before publishing. Before publishing enhancements, expansions or refinements, deterministic evidence-boundary checks catch supported non-observation/negation patterns, then the host runs a separate read-only grounding review with the same local model and original evidence. Its bounded JSON verdict is validated against the proposed section names; an unsupported verdict allows one corrected draft and a fresh review, while repeated unsupported or invalid verdicts fail closed. No unbounded retry is allowed. Source fingerprints are verified after review. The review adds latency and may produce false positives; no model verdict is a semantic proof. The renderer uses `ui/original-links.ts` with Component-owned native click handlers; the host opens an existing TFile, never openLinkText’s missing-note path. Author acceptance examples use fictional evidence and the existing local model only.

Selected literal templates supply headings through the native vault reader; configured templates are removed from evidence snapshots. Their text fingerprints join freshness checks without becoming factual sources. No template code runs. Entry type is carried on the request packet so expansion formatting and Character briefs agree with configured classification.

## Saved-output reliability and performance (D-0042)

The existing expansion frontmatter envelope gains an optional pair of freshness digests; old compatible envelopes remain readable. `core/freshness.ts` hashes sorted vault-relative eligible note paths, text, aliases, resolved links and metadata under the configured project/shared scope, plus classification/template routing and context configuration. It does not treat a generated file as evidence. Used original/template stamps are independently checked through fresh native reads. Pending insertions carry forward their original inventory, updating only the author's inserted target text; they never silently adopt intervening evidence changes.

`core/storage.ts` restricts owner-marker and expansion parsing to actual frontmatter. Library inspection separates supported metadata, unowned legacy Markdown and damaged/unsupported artifacts. No legacy structured schema is inferred or rewritten. A supported standalone expansion is read-only, including during busy-state refresh. Before replacing plugin bytes, storage compares the current file, writes/verifies one previous-version recovery file, rechecks the current file, checks cancellation, writes and verifies the replacement. Explicit restore follows that same guarded path, retaining the displaced bytes. Adapter operations do not provide a cross-process atomic transaction; simultaneous writers remain unsupported. A lost/corrupt first save has no previous version to restore. Recovery lives outside the expanded-tree inventory and outside canonical evidence.

Snapshots use Obsidian's native `cachedRead` for repeated original reads and always overlay source-mode editor buffers; final used-source checks still call `read`. Metadata and resolved links continue to use the native cache. Streaming progress updates only its existing label every 500 ms, preserving the rendered conversation. Expansion event redraws debounce at 250 ms and skip Markdown reconstruction when saved bytes, recovery bytes and stale status are unchanged. Lifecycle cleanup cancels timers and render revisions prevent late publication. Per-operation in-memory `timings` tracks retrieval, aggregate model generation/review, Markdown rendering and storage separately; it persists no telemetry or prose. Synthetic timing measurements are not a native large-vault or model-speed benchmark.


## Shared project boundaries and sidebar structure (D-0043)

`workspace/model.ts` exports a host-independent project resolver shared by workspace project/canon discovery, New Entry, Librarian packets/freshness and ScriptController. Explicit declarations precede configured-root inference and legacy manuscript/Scripts evidence; configured global canon/brainstorm routes and excluded storage override project membership. Organizational Overview/Dashboard/Index/Project Register names (with optional numeric prefixes) do not produce projects. The resolver does not rewrite notes. ScriptController caches the resolver against relevant configuration and invalidates it on native create/modify/delete/rename and metadata events. Writing baselines use that same scope, avoiding separate subfolder identities for custom manuscript routes.

`structure.ts` relocates original source ranges with only necessary newline separators; no Markdown serializer or numbering rewrite is used. Pages stay within their script; panels can move across its pages. Controller opens/reuses a native editor, activates source mode if needed, compares the complete current buffer to the drag snapshot and checks lifecycle state immediately before committing. `applyScriptEdit` uses the existing editorInfoField/EditorView bridge and `commitShortcut` history isolation; its native Editor transaction fallback remains for hosts without that bridge. There are no OS hotkey defaults or new runtime dependencies.

`drag.ts` owns pointer gestures and touch long-press. Pointer handling avoids the Electron HTML drag-session behavior observed during native verification. Payloads retain path, block kind, original offset and text fingerprint; targets reject incompatible kinds/scripts and stale fingerprints. Mouse Escape, pointer cancellation/blur, touch cancellation and view close clean up document-owned listeners. Touch movement before the hold threshold remains ordinary scrolling. Page/panel drop coordinates choose before/after, with a page-header panel drop appending within that page. Existing same-Group script ordering still uses predecessor writes, not editor Undo.

ScriptController caches parsed scripts by path/text/scope, native mtime/size and invalidation version. Open source buffers always override disk text; final order guards retain fresh reads. A serialized, debounced refresh loop coalesces pending events and stops after module teardown. ScriptsView compares only menu choices and selected outline structure, updating its live script map even when DOM reuse is possible; navigation and drag payload factories consult current offsets. ProjectView stages changed Markdown articles with their own Components, reuses unchanged articles, commits after revision checks, and preserves scroll and untouched folds. In-memory read/parse/group timing counters support the synthetic benchmark; they transmit and persist no telemetry.
